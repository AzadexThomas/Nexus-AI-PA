# Private dossier and creditor assistance

The private interface now resolves supply helpers in the same scope as its main router. Browser tests cover Dashboard, conversation, Tasks and Supplies; syntax checks alone did not catch the original reference error.

Authenticated owner requests can retrieve selected sections from a fixed private reference document through the existing signed connector. Responses retain source version/date, distinguish dated reports from current provider records, and grant no execution permission. The full document is not copied into agent knowledge bases, GitHub or ordinary operational logs. Family sessions, unverified callers and ordinary outbound contact calls cannot use this path.

Owner corrections preserve provenance, historical evidence and concurrent revision checks. The database supplies current correction overlays immediately. Background synchronization uses exact existing file identities, optimistic file-version checks, idempotent correction markers and readback of both Markdown and PDF. A failed or partial synchronization stays unconfirmed with a durable retry delay. A hosted preview validated source access without modifying either source file. A subsequent authorized directory-metadata update passed exact readback for both existing files; the updated PDF was rendered for inspection. Identity-secret values were not copied or claimed verified.

Creditor assistance uses a separate voice agent and account-specific structured authorizations. It does not relax the family/contact-call scope. Durable cases distinguish requests, scheduling, dial attempts, representative connection, offers, owner review, uncertain outcomes and confirmed enrollment. A saved blocked request is not a scheduled call. Dispatch checks account identity, servicing destination, institution authorization, source freshness, pause/cost controls and the requested date. Reservations precede provider submission; unknown commitments are never blindly repeated.

The generic offer contract rejects incomplete terms, fees, positive required payments, continuing interest, account closure, adverse reporting, shorter/different durations and prohibited financial commitments. Auto-loan and mortgage modifications always require owner review. An eligible policy result alone cannot execute anything: acceptance also requires a correlated verified call, current account authority and separately verified written terms. Confirmed enrollment requires a matching verified written confirmation, not merely a verbal report or a queue receipt.

Identity secrets remain outside the dossier and ordinary logs. Where a creditor requires owner authentication and no purpose-specific secure disclosure flow is verified, the task is blocked for owner participation. No authentication bypass or account-holder impersonation is supported. The dedicated agent disables audio recording, limits transcript retention and has bounded call duration, concurrency and daily calls.

Validation includes synthetic backend policy/state/access tests, rendered browser views, two hosted all-tools-mocked authentication/unsafe-offer simulations, and bounded production source checks. An earlier combined simulation became inconclusive because safe early termination prevented its later offer criterion from being reached; focused scenarios separately passed. No real creditor call or enrollment was used for testing. Live institution authentication, written-offer ingestion and an actual enrollment outcome remain unverified.

The first real cases are now scheduled to begin with public assistant-authorization inquiries at verified product servicing destinations/hours. This first stage permits no identity-secret or hardship disclosure. The private stage requires a current destination/task/account-bound verification statement, not a generic statement that assistants are allowed. This avoids requiring the institution's telephone verification before a public inquiry can even be dialed. Enrollment remains disabled pending verified written-source handling. Case results and admission failures queue deduplicated status notices to the owner. Existing pause, budget and included-capacity holds apply; the same verified daily financial source is reused for source freshness rather than adding financial polling.

When a finished call has a saved offer, reconciliation retains the offer and asks for owner review. A reserved acceptance takes precedence and stays uncertain until verified confirmation arrives; an offer alone never proves enrollment.

## Written-source execution boundary

The full-text reader is a separate signed action; ordinary reply body limits remain unchanged. The backend uses exact issuer-domain registration, aligned mailbox authentication, direct recipient checks, task-relative freshness, masked account and representative-supplied plan reference. The model receives parsed terms and an immutable source digest, never raw inbox contents. The only automatically supported format is explicit labelled plain text containing all required fields and supported narrative values. Extra material, duplicate fields, links, attachments or unfamiliar wording require review; there is no inference that an omitted fee is zero.

Written receipts retain source/version hashes and bounded field evidence privately. The source is fetched again before acceptance. A case-level reservation prevents parallel offers from creating multiple acceptances. Confirmation must follow reservation, use the same plan reference and match all accepted terms. Background confirmation checks stop after 24 attempts or a one-day window, with increasing delay. They establish evidence only and never repeat acceptance or extend authority. The runtime capability is enabled for this narrow format; actual issuer support and real enrollment remain unverified.

## IVR and provider startup readiness

Language offers are not mandatory navigation commands. The creditor agent stays on English, waits through optional alternate-language announcements, and uses only explicitly announced English/service keys. It never guesses an operator digit or enters protected account/identity information. Two hosted menu regressions cover default and explicit English paths.

Call proof validation reports missing fields separately from mismatched bindings. Registration or provider metadata may be retried at most three times with bounded waits; no submission, acceptance or redial is repeated. An actual mismatch fails immediately. Once metadata is ready, every original agent/case/attempt/destination/line/freshness check still applies, and institution authorization is a separate requirement. Denial records contain validator field names only. Admin forensic replay of saved calls is diagnostic-only and cannot open a session or authorize disclosure. The original transient field failure was not recorded, so its precise historical cause remains unproven.
